## Quality position

Repository quality is checked by a dependency-free release audit and a separate regression suite for the audit rules.

The source gate verifies structure, metadata, links, JSON-LD, shared-shell invariants, accessible labels, duplicate IDs, sitemap integrity, local dependencies, inline event-handler absence, security.txt and selected visual-system invariants.

The source gate is not a substitute for:
- browser/mobile UX verification
- Lighthouse / field Core Web Vitals
- live WhatsApp / phone testing
- Rich Results validation
- Search Console indexing review
- formal legal review

## Evidence policy

NUMUW does not fabricate client logos, testimonials, awards, rankings, revenue, ROI or guaranteed search results.

Proof should become stronger through:
- real cases
- measurable evidence
- public demonstrations
- transparent scope and acceptance
- documented delivery

## Repository hygiene

Engineering experiments and historical QA reports belong under `docs/archive/` or the `bench/` / `.autoresearch/` engineering areas. They are not treated as the public commercial source of truth.

## Release rule

A feature is not considered complete merely because its file exists. Completion requires the relevant source, UX, content, conversion, security, ownership, operational and verification conditions to be satisfied.
