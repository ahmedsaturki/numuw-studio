# NUMUW System Blueprint

Purpose: single source of truth for how NUMUW is positioned, organized, sold, delivered and evolved.

## 1. Core positioning
NUMUW is a founder-led Growth Systems Studio for businesses whose growth is constrained by disconnected marketing, sales, conversion, follow-up, operations or measurement.
The core idea is connected growth, not a menu of services.

Primary fit:
- B2B and industrial businesses with complex buying cycles, RFQs, qualification and follow-up.
- Established service / local businesses where discovery, trust and conversion are the main bottlenecks.
- Property and commerce businesses where digital demand must move into measurable inquiry, purchase or follow-up.

The business may change its commercial focus over time. The architecture must support that without turning the brand into a generic do-everything agency.

## 2. Information architecture
The global public navigation is intentionally fixed:
Home → Solutions → Tools → Products → Company → Resources
Trust, legal and operational references live in the footer and relevant decision pages.

### Solutions
Solutions are audience / problem entry points, not product clones.
- B2B
- Manufacturing
- Website / conversion
- Automation
- Practical AI
- SEO / local visibility
- Brand / identity
- Growth partner
- Real estate
- E-commerce
Each solution page must have its own audience, problem context, evidence, scope, exclusions and next action.

### Tools
Tools are decision accelerators, not entertainment widgets.
- Growth Diagnostic
- Automation Finder
- Growth Project Estimator
- 90-Day Roadmap
- ROI Scenario Calculator
- Website Readiness
- Solution Finder
- Brief Builder
Each tool must answer one meaningful question and produce a next step.

### Products
The commercial ladder is:
1. Diagnose — NUMUW Diagnostic.
2. Build — Digital Kickoff / Automation Sprint / Growth System.
3. Partner — Growth Partner.
No product should exist only because it sounds attractive.

## 3. Buyer journey
Discover → Understand → Self-assess → Compare → Verify → Scope → Commit → Deliver → Handover → Improve
Unclear problem → Solution Finder / Diagnostic.
Clear single need → relevant Solution / Product.
Multi-layer need → Growth System.
Ongoing optimization need → Growth Partner.
Ready-to-talk buyer → WhatsApp / phone / Brief Builder.

## 4. Homepage hierarchy
1. Clear business problem and proposition.
2. Who NUMUW is for.
3. What bottlenecks NUMUW solves.
4. System layers.
5. How the engagement works.
6. Product / commercial entry points.
7. Proof / evidence standard.
8. FAQ / risk reduction.
9. One obvious next action.
The homepage may have a distinct visual treatment, but its navigation, CTA logic, terminology and design tokens must remain compatible with the global system.

## 5. Proof system
NUMUW does not compensate for a young portfolio with invented proof.
Evidence hierarchy:
1. Real client results with permission and source.
2. Dated first-party measurements.
3. Public shipped work / artifacts.
4. Process evidence: QA, documentation, ownership and handover.
5. Founder / team expertise where verifiable.
6. Testimonials only when genuine and attributable.
Never publish invented logos, fabricated testimonials, unsupported rankings, fictional ROI, fake awards, guaranteed search positions or synthetic client stories presented as real.
A case study should state: Context → Problem → Baseline → Decision → Work → Evidence → Limits → Lesson.

## 6. Content rules
Every indexable page must have an independent job.
Do not create pages only to capture more keywords.
Before adding a page, answer: who needs it, what decision it changes, what new information it provides, what proof belongs on it, where it routes the buyer next, and why it should be indexable.

## 7. Design system
The public system uses shared tokens in assets/css/numuw.css.
Rules: one palette, one typography system, one spacing rhythm, one button vocabulary, one card/panel language, one focus treatment, one mobile behavior pattern, consistent radii/shadows, and documented reasons for exceptions.
The homepage may use home.css for art direction, but should consume the same semantic brand values.

## 8. Accessibility
Keyboard-operable navigation; visible and unobscured focus; practical hit sizes; semantic controls before ARIA; skip link; logical heading hierarchy; descriptive labels; live announcements for dynamic results; reduced-motion support; no hover-only information; no critical control dependent on JavaScript without a usable fallback.

## 9. Conversion instrumentation
The browser layer measures intent, not revenue.
Allowed intent events: CTA intent, tool start, tool completion.
Business truth remains outside the browser: qualified conversation → proposal → won work.
Never infer revenue, qualification or ROI from a click.

## 10. Commercial operating system
Every engagement should have discovery record, baseline/assumptions, written scope, exclusions, dependencies, client responsibilities, change-request process, milestones/payment terms, acceptance criteria, ownership terms, support window and handover checklist.
Sensitive credentials do not belong in chat, source files or general project documents.

## 11. Release system
Before merge: static audit, metadata/canonical/JSON-LD, internal links, accessibility invariants, dependency review, accidental-corruption review and claim review.
Before production sign-off: Pages deployment, live browser/mobile verification, Lighthouse/field CWV, external CTA verification, Rich Results, Search Console and legal review where required.
A source-only pass never substitutes for a live-production pass.

## 12. Competitive learning rule
NUMUW should learn mechanisms, not copy brands.
Blend demonstrates the value of a coherent B2B category, connected brand + website + growth infrastructure, and case studies integrated into the commercial engine.
Strong B2B sites make buyer journeys explicit and serve different stakeholder needs instead of mirroring internal org charts.
Evidence works best when tied to a real problem, defined intervention and inspectable context.
Design quality is subordinate to clarity, information architecture, trust and action.

## 13. Change control for NUMUW itself
A new page, product, tool, integration or brand element is not done until it is connected to architecture, content strategy, conversion route, measurement plan, proof requirement, accessibility, performance budget, legal/trust implications, QA and sitemap/indexing where appropriate.
If it does not fit the system, redesign the system before adding the asset.

## 14. North-star question
Does this make NUMUW easier to understand, easier to trust, easier to buy from, easier to deliver with, or easier to improve?
If not, it is probably noise.
