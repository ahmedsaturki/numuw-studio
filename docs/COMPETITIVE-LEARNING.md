# NUMUW Competitive Learning Register

**Updated:** 2026-10-05

This is a learning register, not a competitor imitation file. NUMUW studies successful mechanisms, validates them against its own market and constraints, and deliberately avoids copying another company's brand, language, visual identity or unsupported claims.

## 1. B2B website strategy

### Blend

Observed mechanism:
- Starts with audience, buyer journeys and commercial goals before sitemap/design.
- Connects information architecture, navigation, content, SEO/AEO, functional requirements and audience pathways.
- Treats case studies as part of the commercial engine, not a detached portfolio page.
- Connects brand, website, CRM and growth infrastructure when the business case requires it.

NUMUW implication:
- The website architecture must begin from buyer decisions.
- Every solution page needs a distinct audience/problem/job.
- Products should be reachable after diagnosis or a clear need.
- Proof must appear inside the journey, not only under Company.

Source:
https://www.blendb2b.com/websites/website-strategy

## 2. Evidence-led selling

Successful case-study systems make the intervention inspectable:
- context
- problem
- work
- evidence
- limits
- lesson

NUMUW implication:
- No invented logos or testimonials.
- As real work accumulates, every case should show a verifiable baseline and outcome where permission allows.
- Process evidence such as QA, documentation, ownership and handover is valuable before a large outcome library exists.

Sources:
https://www.blendb2b.com/case-studies
https://www.blendb2b.com/work/breathe

## 3. Buyer experience

B2B buyers do not all arrive with the same question. A strong site supports multiple paths without making the user understand the company's internal organization.

NUMUW implication:
- Global navigation is organized around the visitor's decision: Solutions, Tools, Products, Company, Resources.
- Sector pages route by business context.
- Solution Finder and Diagnostic reduce uncertainty.
- Product pages explain fit/non-fit instead of pushing every visitor toward the largest package.

## 4. Accessibility as product quality

Vercel's current interface guidance emphasizes:
- keyboard-operable flows
- visible and unobscured focus
- generous hit targets
- 44px mobile targets
- labels for form controls
- forgiving interaction design

WCAG 2.2 also formalizes Focus Not Obscured and Target Size requirements.

NUMUW implication:
- Accessibility is part of the shared design system, not a final audit.
- Shared focus styles, navigation semantics and tool labels must remain centralized.
- Fixed WhatsApp and sticky UI must not hide focused controls.

Sources:
https://vercel.com/design/guidelines
https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/

## 5. Search quality

Google's current guidance emphasizes original, accurate, people-first content and warns against scaled pages created mainly to manipulate rankings.

NUMUW implication:
- Do not add pages only because a keyword exists.
- A page earns indexability by having a distinct decision/job and material information.
- Tools should be genuinely functional, not fake generators or lead walls.
- Structured data must accurately represent visible content.

Sources:
https://developers.google.com/search/docs/fundamentals/creating-helpful-content
https://developers.google.com/search/docs/essentials/spam-policies
https://developers.google.com/search/docs/appearance/structured-data/sd-policies

## 6. Structured data and hierarchy

Google recommends using Organization structured data where it helps describe the organization and BreadcrumbList markup that represents a typical user path. Structured data does not guarantee a rich result; it must accurately match visible content.

NUMUW implication:
- Keep organization identity concentrated on the home/about layer.
- Use BreadcrumbList to clarify the actual information architecture.
- Validate deployed pages with Rich Results and URL Inspection instead of assuming valid JSON-LD equals eligibility.

Sources:
https://developers.google.com/search/docs/appearance/structured-data/organization
https://developers.google.com/search/docs/appearance/structured-data/breadcrumb

## 7. Failure patterns to avoid

### Fake proof
Creates short-term confidence but destroys trust and can create policy / reputational risk.

### Service sprawl
A long list of capabilities makes the brand look unfocused. NUMUW should sell an outcome-oriented system and use services as implementation components.

### Keyword page factories
Many thin pages can increase maintenance while reducing actual value. Distinct decision value beats page count.

### Design-first architecture
A beautiful page with weak navigation, unclear audience paths or no commercial next step is still a weak sales asset.

### Tool theatre
A calculator that produces a number without useful assumptions, caveats or next action is not a serious decision tool.

### Platform lock-in
A growth system that requires one vendor for ownership or operation creates avoidable dependency. Prefer client-owned assets and documented dependencies.

### Automation without controls
Automation that lacks exception handling, ownership, logging, rollback or documentation transfers risk rather than removing work.

## 8. NUMUW benchmark rule

For every significant change ask:

1. What successful mechanism does this learn from?
2. What evidence suggests it works?
3. What is the NUMUW-specific adaptation?
4. What trade-off or failure mode does it introduce?
5. How will we know whether it worked?

A benchmark is not a reason to add a feature. The feature must still improve understanding, trust, buying, delivery or measurable improvement.
