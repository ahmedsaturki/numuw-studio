# NUMUW Page Contracts

This file defines what each public page type must contain and what it must not become.

## Home

Must:
- state category and audience
- state differentiated promise
- establish trust without fabricated proof
- expose the primary next step
- expose products/tools without creating decision overload
- route to Solutions, Tools, Products and Proof

Must not:
- become a sitemap
- list every capability without hierarchy
- claim results without evidence

## Solution

Must:
- identify audience and problem
- explain mechanism
- define fit/non-fit
- show deliverables or operating model
- route to the right tool/product/contact action
- use unique page-level copy

## Tool

Must:
- explain exactly what it calculates/assesses
- make assumptions visible
- keep user-entered data local unless explicitly disclosed otherwise
- announce results accessibly
- route to a next action

Must not:
- imply external data was analyzed when it was not
- present a scenario as a guarantee

## Product

Must:
- name the buyer
- explain the problem
- explain scope and exclusions
- list deliverables
- define acceptance
- explain dependencies/ownership
- give starting investment or explain how it is scoped
- provide a primary commercial CTA

## Proof

Must:
- distinguish verified case evidence from illustrative material
- expose source/scope/time context for metrics
- explain the evidence standard

Must not:
- fabricate logos, testimonials, awards, rankings, ROI or before/after claims

## Document

Must:
- be printable
- be operationally useful
- have clear revision/status language
- avoid becoming a second acquisition site

## Legal

Must:
- state its operational scope
- avoid pretending to be legal advice
- align with actual data practices

## 404

Must:
- recover navigation
- remain noindex
- not appear in the sitemap
