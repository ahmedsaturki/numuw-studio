# NUMUW Offer Architecture

## The buying problem

Customers should never have to decide among six services before they understand the problem. The site therefore uses a diagnostic-first ladder.

## Offer families

| Level | Customer question | Core output |
|---|---|---|
| Diagnose | What is wrong / what matters first? | baseline + priority + recommended path |
| Sprint | Can we fix one bottleneck? | bounded implementation + QA + handover |
| System | Do several layers need to work together? | integrated growth system |
| Partner | Who keeps improving this after launch? | recurring priorities + measurement + optimization |

## Product rules

A product is not considered productized because it has a name. It becomes productized when the buyer can understand scope, constraints, inputs, output, acceptance and next step before purchase.

## Pricing rule

Published numbers are anchors, not blind quotes. The final commercial scope controls.

## Anti-grab-bag rule

Do not bundle every available capability into every offer. Bigger is not automatically better. Use the smallest coherent intervention first, then expand only when evidence supports expansion.

## Delivery rule

Every Sprint or System begins with a shaped scope and a defined appetite / time box. Scope is allowed to flex before acceptance so quality and completion are protected.
