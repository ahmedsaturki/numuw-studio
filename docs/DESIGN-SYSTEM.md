# NUMUW Design System

## Design objective

The visual system should communicate **credible operator + practical growth system**, not generic luxury agency, SaaS dashboard or template marketplace.

## Tokens

Primary:
- Navy: #081321
- Navy 2: #10243d
- Teal: #08766e
- Teal accent: #21c6b6
- Gold: #d9a441
- Background: #f5f7fa
- Paper: #ffffff
- Ink: #122033
- Muted: #5f7084
- Line: #dfe6ee

## Layout

- One shared content max-width.
- One shared spacing scale.
- Consistent card radius and border treatment.
- Consistent CTA hierarchy.
- No page-specific header/footer redesign unless a documented exception exists.
- No decorative element may reduce legibility or hide focused content.

## Typography

Use system fonts only.
Headings are high-contrast and compact.
Body copy is readable at mobile widths.
Mixed Arabic/English terms should use natural direction handling rather than hard-coded layout hacks.

## Components

Canonical components:
- skip link
- sticky header
- primary navigation
- language control
- menu control
- primary / secondary button
- eyebrow
- lead
- card
- steps
- notice
- CTA section
- footer
- form field
- result/status region

## Interaction

- Keyboard-first behavior must equal pointer behavior.
- Focus must remain visible and must not be hidden behind sticky layers.
- Buttons must have explicit types.
- Dynamic results use status announcements where appropriate.
- Reduced motion is respected.

## Mobile rule

Mobile is not a shrunken desktop. Navigation, CTA width, content order and form density should be intentionally readable at small widths.

## Visual consistency rule

A visitor moving from Home → Solution → Tool → Product → Contact should feel they are still inside the same system. The copy can change; the shell, interaction language and hierarchy should not.
